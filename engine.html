MitiruEngine

「必要なものしか画面に出さない」を哲学にした自作 C++ ゲームエンジン。 Unity / Godot のような全機能エディタの対極 ── 1 ツール = 1 関心事 = 1 ウィンドウ。CLI が一級市民で、GUI エディタは提供しません。ゲームのロジックは C++、メニューや HUD は HTML/CSS で書けます。

概要

使う側ではなく書く側からグラフィックスとエンジンの低レイヤーを押さえるための足場として開発しています。決定論的な実行とリプレイ、タイムトラベル・インスペクタ、サブシステムの単独起動 ── 「裏側で何が起きているか見える」ことを価値の中心に置いた設計です。

なぜ自分でエンジンを書くのか

Unity / Godot / Unreal / Siv3D はゲームを作るだけなら困りません。それでも書くのは、ゲームが画面に出るまでに何がどう動くかを、使う側でなく書く側から知っておきたいからです。

目的はエンジンそのものではなく、ゲームを深く作れる人間でいるための足場。ゲーム制作は並行して進め、そこで詰まった課題をエンジンへ書き戻しています。

設計哲学 ── アトミックツール

すべての設計判断は「必要なものしか画面に出さない」から派生しています。Unity / Godot の「50 パネルが同時に見える」状態の対極です。

  • 1 ツール = 1 関心事 = 1 ウィンドウ ── Renderer / Audio / FSM / インスペクタはそれぞれ独立した別ウィンドウ
  • デフォルトでは何も開かない ── 開発者が必要に応じて窓を開く pulled UI
  • CLI が一級市民 ── mitiru new / build / run / watch / replay / inspect で全機能にアクセス。IDE は optional（VS でも Vim でもメモ帳でも）
  • Code-first、インスペクタは観察専用 ── state を書き換える GUI エディタは作らず、Chrome DevTools 型の「観察する GUI」だけを提供

Game-as-DLL とホットリロード

ゲームコードは DLL で、ホスト（mitiru_host.exe）がロードしてメインループを駆動します。編集 → ビルド → state を保持したまま即時リロード。Handmade Hero のパターンをエンジン哲学に組み込みました（ADR 0005 / 0015）。

Host–Game 境界は POD の C-ABI だけ。ゲームは Engine* を一切持たず、(memory, input, dt) を受けて (state push / inspectable / JS 実行の intent) を返す純関数に近い形です。「engine.foo() で済ませる」誘惑が構造的に消えるため、後述のタイムトラベルとリプレイが GameMemory の memcpy だけで動く設計保証になります。

書き味はこれだけです。struct に状態を持ち、update / draw を書いて 1 行で DLL の入口を作ります。

struct MyGame {
    float x = 600;
    int   score = 0;

    void update(Input in, Hud hud, float dt) {
        if (in.down(Key::Right)) x += 320 * dt;   // → で右へ
        hud.set("view.hud.score", score);         // HTML 側へ push
    }
    void draw(Screen& s) { /* 四角や文字を描く */ }
};
MITIRU_GAME(MyGame)   // これだけで DLL の入口ができる

HUD は HTML 側で <span data-m-text="view.hud.score"> と書くだけで受かります。JavaScript は書きません。bridge は signal-only で、状態の所有は常に C++ 側です。

差別化の 5 軸

1. HTML/CSS で UI が書ける C++ エンジン

gameplay は C++、メニューや HUD は CEF 上の HTML/CSS。Web 開発の知識がそのまま UI に使え、CSS アニメーションも効きます。両者は signal だけでやり取りします。

2. タイムトラベル・インスペクタ

全フレームの state を ring buffer に記録し、巻き戻して観察できます。「なぜ HP が 50 になったか」を 30 フレーム前に戻って原因の 1 行まで特定する、が実際にできます。プレイ中に T キーで過去 5 秒をスクラブ。

3. 全サブシステムの単独起動

mitiru renderer / mitiru audio のように、各サブシステムが個別の CLI コマンドで立ち上がります。CEF のコールドスタートもフォントアトラス構築も全部省くので 1 秒以下で起動。シェーダの反復にも、描画バグの切り分け（これが動くなら blame は gameplay 層）にも効きます。

4. 決定論 + 自動リプレイ

入力と乱数 seed を毎プレイ自動記録し、mitiru replay run.json でヘッドレスでも bit-exact に再現。実際のプレイ記録がそのまま回帰テストになります。リプレイ再生中にタイムトラベルを開く、という組み合わせも可能です。

5. モジュラー・サブウィンドウ

インスペクタやコマンドパレットは OS レベルで独立した別ウィンドウ（ADR 0004）。サブモニタへドラッグでき、片方が落ちても他方は生き、ゲーム画面のスクリーンショットに余計なものが映りません。mitiru inspect <pid> で走っているゲームに後から繋げます。

CLI

エンジンの正規の入口です。Go 製の mitiru-cli が CMake を隠蔽し、Cargo / go run の感覚でゲームを書き始められます。

mitiru new my_game     # DLL skeleton の scaffold
mitiru run             # build + host 起動
mitiru watch           # src/ 編集で state 保持のままホットリロード
mitiru replay run.json # 記録済み入力を決定論的に再生
mitiru renderer        # renderer サブシステム単独起動
mitiru inspect <pid>   # 走っているゲームを別窓で観察
mitiru doctor          # VS / CMake / engine cache を 3 行で診断

アーキテクチャ

header-only のレイヤースタックです。gameplay は全て C++ で、CEF は UI オーバーレイとインスペクタ層 ── gameplay 層ではありません。

+-------------------------------------+
| user code (game DLL)                |
+-------------------------------------+
| P0 primitives                       |  FSM, Timer, SceneRouter,
|                                     |  JsonBinding, SaveSchema, ...
+-------------------------------------+
| Engine subsystems（機能別に独立）   |  Renderer, Audio, Physics,
|                                     |  Input, Scene, ECS, Network
+-------------------------------------+
| Platform backends                   |  GLFW | Win32 | SDL2
|                                     |  | Emscripten | Headless
+-------------------------------------+
| Graphics: IDevice 抽象の裏で        |  OpenGL | DX11 | DX12 |
|                                     |  Vulkan | WebGL | WebGPU | Null
+-------------------------------------+
        ↑ CEF UI / Inspector layer（観察専用 + HTML/CSS UI）

GPU バックエンドは全部 IDevice という同じインターフェイスの裏に隠してあります。GPU が無い CI 環境では NullDevice に自動で落とすので、1,800+ のテストはヘッドレスでそのまま緑で回ります。

MitiruEngine で動いているもの

エンジン単体ではなく、実際にゲームに使えている状態かどうかが重要なので、現時点で MitiruEngine 上で動いているものを並べておきます。

  • ハトを育てよう（リメイク） — 2023 年に TyranoScript で書いた原作を、CEF Hybrid + mitiru.novel VM で完全移植。バックログ・既読管理・セーブロードなどの追加要素も入った状態で動いています。
  • かえるクレープへようこそ — Godot 版を経て、現在 MitiruEngine の WASM ビルドへ移植中（1.0.0-rc1）。Playwright による E2E テスト、テーマトークン、itch.io 向けパッケージングまでセットアップ済み。
  • 同梱サンプル — ブロック崩し（breakout）、よけゲーム（dodge）、サバイバル（hello_game）など。hello_game は 1 本でタイムトラベル・リプレイ・サブウィンドウの 3 軸に触れる参照実装になっています。
  • NPR 輪郭線の時間安定化 — motion vector / objectId バッファから GPU パスまでエンジン上で実装した実験（Lab）。

エンジンを書く作業と、エンジンでゲームを作る作業を、両方を行き来しながら進めています。
