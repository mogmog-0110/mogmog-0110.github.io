Live2D × Direct3D 12

Live2D の公式 SDK が対応していない Direct3D 12 で、モデルを描画する仕組みを実装しました。公式の D3D11 レンダラを読み解き、クリッピングマスク、オフスクリーングループ、advanced blend を含む描画手順を D3D12 で再現しています。

2026年 個人開発 MitiruEngine DirectX 12 Cubism SDK 5

成果

自作の MitiruEngine 上で、8体の公式モデル（Haru / Hiyori / Mao / Mark / Natori / Ren / Rice / Wanko）が動作します。

背景ステージ、公式相当のフレーミング、マウス追従、タップモーション、物理、目パチ、呼吸に対応しました。クリッピングマスク、オフスクリーン、advanced blend を使うモデルも表示できます。

取り組んだ課題

MitiruEngine は Direct3D 12 製ですが、Live2D 公式 SDK の対応先は OpenGL、D3D11、D3D9、Metal、Vulkanで、D3D12 は含まれていません。

そこで、公式の CubismRenderer_D3D11 がモデルを描く手順を調べ、同じ処理を D3D12 の API で一つずつ実装しました。

Live2D のモデルは、テクスチャを貼った複数のメッシュから成ります。それぞれの描画順、不透明度、ブレンドモード、マスク、所属するオフスクリーングループは、モーションに応じて毎フレーム変化します。この変化を反映しながら正しい順序と合成方法で描く必要がありました。

実装した描画機能

  • 描画順の処理
    ドロウアブルとオフスクリーンを csmGetRenderOrders の順に走査します。描画順は毎フレーム並べ替え、モーションによる重なり順の変化を反映します。
  • クリッピングマスク
    マスク形状を専用バッファへ先に描き、その結果を使ってモデルの一部を切り抜きます。被クリップごとに 256² のマスクバッファを使う高精度経路を実装しました。
  • オフスクリーングループ
    パーツの集合を個別のレンダーターゲットへ描き、不透明度、ブレンドモード、乗算色、スクリーン色を使って親へ合成します。入れ子とマスク付きオフスクリーンにも対応しています。
  • advanced blend
    固定機能だけでは表せない合成のため、描画先をコピーし、専用シェーダでピクセルごとに計算します。公式シェーダ CubismBlendMode.fx の18種類のカラー合成と5種類のアルファ合成を HLSL へ移植しました。

D3D12 での設計

D3D11 では内部で処理される部分も、D3D12 では明示的に管理する必要があります。

  • 三重バッファリング
    エンジンは3フレームを同時進行させます。GPU が前のフレームを参照している間に CPU がデータを上書きしないよう、頂点バッファと定数バッファを三重に持たせました。
  • リソース状態の管理
    レンダーターゲットとシェーダリソースの切り替えや、advanced blend のコピーに必要な COPY_SOURCE、COPY_DEST への遷移を、描画処理の境界で管理します。
  • 描画状態の事前準備
    マスク用と下地コピー用の SRV を含むルートシグネチャを設計し、ブレンド種別とカリングの組み合わせに応じた PSO を事前に生成しました。
  • 公式実装との規約合わせ
    頂点、乗算済みアルファ、ブレンドステート、MVP、UV の Y 反転、テクスチャフォーマットを公式 D3D11 レンダラと突き合わせました。
