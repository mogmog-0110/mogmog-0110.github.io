Live2D × Direct3D 12

自作の MitiruEngine は Direct3D 12 製ですが、Live2D 公式 SDK は D3D12 に対応していません（OpenGL / D3D11 / D3D9 / Metal / Vulkan のみ）。そこで、公式の D3D11 レンダラ CubismRenderer_D3D11 が内部で何をしているかを読み解き、その描画手順を一つずつ D3D12 で再実装しました。Cubism 5 のクリッピングマスク・オフスクリーングループ・advanced blend を含む、フルセットの移植です。

動いているもの

背景ステージ・公式相当のフレーミング・マウス追従・タップモーション・物理・目パチ・呼吸まで含めて、8 体の公式モデル（Haru / Hiyori / Mao / Mark / Natori / Ren / Rice / Wanko）が D3D12 上で動きます。クリッピングマスク・オフスクリーン・advanced blend を使うモデルも含みます。

公式 D3D11 レンダラは何をしているか

Cubism のモデルは、テクスチャの貼られたメッシュ（ドロウアブル）の集まりです。各ドロウアブルは「描画順・不透明度・ブレンドモード・どのマスクで切り抜くか・どのオフスクリーンに属すか」といった情報を持ち、これらはモーションに応じて毎フレーム変わります。公式の CubismRenderer_D3D11 は、これを次の段で描いています。

  • 描画順の走査（DrawObjectLoop）。ドロウアブルとオフスクリーンを csmGetRenderOrders の順で1本のストリームにまとめ、_currentOffscreen という入れ子の状態を持ちながらフラットに走査する。
  • クリッピングマスク。あるドロウアブルが別のドロウアブル（の形）で切り抜かれる場合、マスク形状を専用バッファに先に描き、本体を描くときに (1 − mask) を掛けて切り抜く。
  • オフスクリーングループ（Cubism 5）。パートの集合を一旦自前のレンダーターゲットへまとめて描き、親へ「ブレンドモード＋不透明度＋乗算/スクリーン色」で合成する（入れ子可）。
  • advanced blend。Normal / Add / Multiply 以外の高度な合成は、固定機能のブレンドでは表せない。そこで合成先（描いている下地）をコピーし、専用シェーダで 18 種のカラー合成 × 5 種のアルファ合成を1ピクセルずつ計算する。

公式サンプルは、この一連を GL / D3D11 / Metal / Vulkan の各バックエンドで「同じ絵」が出るように作られています。D3D12 はそこに無いので、同じ手順を D3D12 の API で書き直す、というのがこの移植です。

D3D12 へ、一つずつなぞって実装

公式の各段を、対応する D3D12 の機能でそのまま再現しました。

  • DrawObjectLoop。同じフラット走査＋オフスクリーン連鎖で移植。描画順は毎フレーム変わるので毎フレーム並べ替え直す（ここを読み込み時に固定すると、タップなど強いモーションの瞬間に重なり順が崩れる）。
  • クリッピングマスク。高精度経路（被クリップごとに 256² のマスクバッファへ形状を描く）で実装。マスク生成行列（model→マスク NDC）とサンプリング行列（model→UV、Y 反転）を公式 SetupMatrixForHighPrecision と同じ式で算出。
  • オフスクリーングループ。各グループが自前のレンダーターゲットを持ち、親へブレンド合成。マスク付きオフスクリーンにも対応。
  • advanced blend。公式シェーダ CubismBlendMode.fx の 18 カラー × 5 アルファ（Porter-Duff）をそのまま HLSL へ移植。非互換ブレンドのドロウアブルは「下地コピー → 専用シェーダで合成 → 結果で置き換え」する。ブレンドモード値は color = mode & 0xFF / alpha = (mode >> 8) & 0xFF でデコード。
  • 細部の規約合わせ。頂点・乗算済みアルファ（premultiplied）・ブレンドステート・MVP 規約（行優先 mul(pos, M)、UV の Y 反転）・テクスチャフォーマット（R8G8B8A8_UNORM 非 sRGB）まで、公式 D3D11 と一つずつ突き合わせて揃えました。

D3D12 ならではの工夫

D3D11 では中で隠れていて、D3D12 だと自分で面倒を見る必要があった部分です。

  • 三重バッファリング。エンジンは 3 フレームを同時進行（frames-in-flight）させています。CPU が毎フレーム書き込む頂点バッファ・定数バッファを、GPU が前のフレームを読んでいる最中に上書きしないよう、3 重に持つ必要があります。ここを単一バッファにすると、半分書きかけのデータを GPU が読んで全体がちらつき、マスクやオフスクリーンの合成も崩れます（D3D11 ドライバが内部で吸収してくれていた所）。
  • 明示的なリソース状態管理。レンダーターゲット⇄シェーダリソースの遷移、advanced blend の下地コピーに使う COPY_SOURCE / COPY_DEST の遷移などを、描画段の境界で自分でバリアを張って管理します。
  • ルートシグネチャ・ディスクリプタヒープ・PSO の事前設計。マスク用 SRV・下地コピー用 SRV を含むルートシグネチャ、ブレンド種別 × カリングの組み合わせ分のパイプラインステート（PSO）を事前に生成。D3D11 のように状態をその場で切り替えるのではなく、あらかじめ全パターンを用意しておく D3D12 の流儀に合わせています。
  • マスクバッファの精度選択。多くのマスクを持つモデルでも目などの境界が崩れないよう、低精度のタイル分割パッキングではなく、被クリップごとにフルバッファへ描く高精度経路に統一しました。
