オスカーのガーデニング

オスカーが種をまくリズムを聴き、次の小節で同じ位置へ届く芽に水をやるタイミングゲームです。種まきと水やりの音を別の小節に分け、呼びかけと応答の形にしました。自作の MitiruEngine 上で、ゲームの全状態を 1 個の構造体にまとめて開発しています。

開発中 2026年 個人開発 MitiruEngine C++20 DirectX 12 HTML / CSS HUD

ゲームの内容

暗い画面でのオスカーとの会話から始まり、音量調整を経て、庭が降りてきたまま本編へ移ります。プレイ時間が 10 分に満たないため、開始前の選択画面は置いていません。

  • 呼びかけと応答：オスカーが種をまく小節と、プレイヤーが水をやる小節が交互に来ます。種は 1 小節、4 拍で判定線へ届き、種をまいた位置と水をやる拍が 1 対 1 で対応します。
  • 拍の変化：食う、連打、溜め、長押し、2 レーンを小節ごとに組み合わせています。
  • 2 レーン：マウスで手前、キーで奥を操作します。同じフレームにノーツが来ても、両方を処理できます。
  • 時間の進行：本編の進行に合わせて空の色が朝から日暮れへ変わり、速度が上がる終盤ほど日が沈みます。
  • 結果表示：咲かなかった本数を基準に 4 段階へ分け、結果を会話で伝えます。

通常ステージは 26 ターン、131 ノーツ、約 1 分 33 秒です。隠しステージは 29 ターン、220 ノーツで、0.25 刻みの連打と長い走りを中心にしています。

隠しステージへ入る操作は、音量調整画面でオスカーの顔を 10 回つつくことです。回数は表示せず、つつくたびに合図音の音程が上がります。

設計したこと

音を基準にした判定

判定補正は音声出力のレイテンシだけで決めています。プレイヤーが叩くタイミングの傾向は計測していますが、判定には使いません。画面への合わせ方によって、判定の基準が音から表示へ移ることを避けるためです。

速度の上げ方

速度は 1.0 から 1.5 まで段階的に上がり、最後の 1.5 が最も速い構成です。以前は速度を上げたあとに戻していましたが、再加速のたびに違和感が出たため変更しました。高速帯は鏡写しの変種で構成し、テンポ感が崩れやすい、まばらな裏拍だけのパターンは配置していません。

効果音

効果音は「散って落ちる」「ばしゃーっと広がる」といった場面の動きに合わせて作り直しました。長押し中は 1 つの音を継続して鳴らし、短い音をつないだ際の継ぎ目や、離した瞬間の急な切れを防いでいます。

種まきと水やりでは別の音を使います。空振りではスコアを変えず、小さな水音だけを返します。しおれる音は鳴らしません。何も失っていない場面で音を出すと、損失が起きたように伝わるためです。

譜面と台本の編集

譜面と台本は assets/stage.txt にまとめ、プログラムを変更せず編集できるようにしています。実行中に書き換えて R キーを押すと、再ビルドせず反映されます。

ファイルを読み込めなかった場合は既定値へ切り替えず、理由を画面に表示します。編集内容が反映されない原因を確認できるようにするためです。

実装

全状態を 1 個の構造体にまとめる

ゲームの全状態は OscarRhythm という 1 個の構造体に入っています。ポインタと std::vector を含まず、構造体全体をコピーできる flat POD とし、コンパイル時に static_assert で制約を確認しています。内部に std::vector を持つテクスチャは、この構造体の外に置きました。

この構成により、MitiruEngine の機能をそのまま利用できます。毎フレームの状態を記録して巻き戻す、入力を記録してリプレイする、構造を申告して実行中の全フィールドを外部から観測するといった処理です。このページ固有の履歴保存コードは書いていません。

音声クロックへの予約再生

カウントイン、種まき、手本の水やりなど、譜面で時刻が決まる音は音声クロック上へ事前に予約します。フレームの先頭で再生すると最大 16 ms のずれが生じ、音を基準にした入力判定にもばらつきが出るためです。予約した音はサンプル単位で再生されます。

プレイヤーの入力に応じる音は、再生時刻を前もって決められないため、その場で再生します。

判定幅と入力の救済

Perfect は ±45 msで、1 拍の約 9％です。Good は ±90 msです。句の先頭と、句の末尾を遅れて押した場合だけ、判定幅を 1.25 倍にしています。構えの遅れと、終わり際の入力を拾うためです。

長押しは、押し始めと離した時点のうち、低いほうの判定を採用します。離す判定の幅は 1.6 倍です。離す操作は押す操作より精度が下がり、種まき音の減衰につられて遅れる傾向があるためです。

C++ と HTML / CSS HUD

庭、苗、じょうろ、判定演出は C++ で描画し、会話、音量パネル、立て札、結果表示は HTML と CSS で構成しています。C++ 側では文字を描画せず、フォントアトラスの生成も無効にしています。

1 拍分の画面幅は、長押しに使う畝の画像の実寸 203 px に合わせました。画像を伸縮せず、表示される帯の長さと入力時間を一致させるためです。

ノーツ数やパターン数が上限を超えた場合は、ステージの実行中ではなく読み込み時に停止します。該当ターンまで進めなくても、データの問題を確認できます。

デスクトップ版とブラウザ版で同じゲームコードを使う

デスクトップ版ではゲームを DLL にして、MitiruEngine のホストから読み込みます。ブラウザ版ではゲームとゲームエンジンを 1 個の wasm に静的リンクし、Emscripten と WebGL で動かします。

ゲーム側のコードは実行環境を判定しません。ホストから受け取る入力と、ホストへ返す描画依頼がデスクトップ版とブラウザ版で同じ形式になっているためです。
