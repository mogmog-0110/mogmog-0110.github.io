FRUIT DROP

とけて、かたまる。盤面の物性そのものが変わる落ちものパズルです。GPU 物理（PB-MPM・最大 65,536 粒子）の上に古典の落ちものルールを載せ、自作の MitiruEngine で動かしています。物理が「演出」ではなく「ルールそのもの」になることを狙った作品です。

SCREENS

どんなゲームか

世界の「やる気」が波のように満ち引きして、積んだブロックの材質が カチカチ → 硬ゼリー → 柔ゼリー → 液体 へ連続変化します。相が変わると消去ルールも変わります。

  • カチカチ — 物理は時間停止。普通の落ちものパズルとして横一列を消す
  • 硬ゼリー — 盤面がぷるぷる揺れ始める。形が保たれている間はラインも消せる
  • 柔ゼリー〜液体 — 積んだものが溶けて流れる。同色を壁から壁までつなぐと消える
  • 再結晶 — 冷えて固まると、流れた地形が灰色の「大地」として焼き直される。大地は消しても半額だが、直後 3 秒は得点 ×3 のコンボ窓が開く

「溶ける前に消すか、流してから固めて整地するか」── 波を読んで戦略を切り替えるのがこのゲームの核です。

やったこと

  • EA 公開の PB-MPM（WebGPU 実装）を DirectX 12 へ移植 ── compute カーネル 8 本、間接ディスパッチ、bukkit 空間分割をそのまま HLSL / DX12 API に書き直し
  • その物理の上にゲーム層を実装: SRS 回転（壁蹴り）、7-bag 乱数、DAS、ホールド、T スピン判定、着地時のピース粒子化
  • 相転移システム: 凍結相は物理を完全停止（時間停止＝鉄の感触）、溶解相は物理再開。閾値はヒステリシス付きで明滅を防止
  • 描画: 粒子をメタボール蓄積（MRT）→ しきい値合成するトゥーン調パイプライン。落下ピースも粒子と同密度のスプラットで描いて質感を統一
  • HUD は HTML/CSS（CEF オーバーレイ）、BGM/SE は波形生成のチップチューン（やる気と連動して音程が崩れる）
  • 決定論リプレイを回帰テストとして使う開発フロー（後述）と、配布パッケージング（実行一式 zip）

設計

責務は 4 つに割っています。

GPU (DX12 compute)   物理。PB-MPM 8 カーネル + 間接ディスパッチ
CPU (C++)            ルール。ピース操作・消去判定・スコア・相の波
HTML/CSS (CEF)       見た目。HUD は状態 push を受けて描くだけ
JSON 風 signal       C++ → JS は一方向 push のみ。ロジックは C++ が単独所有

CPU 側の当たり判定は「前フレームの格子 readback」を使います。GPU との同期点を増やさず、1 フレームの遅延を許容する設計判断です。占有判定は二重モデルにしました ── 凍結相はセル帳簿（frozenOcc）でビタッと決定的に、溶解相は粒子の平均質量で有機的に。「カチッと嵌まる」と「ぬるっと沈む」が同じコードパスに同居しません。

モジュール構成は 1 関心事 = 1 ファイル。GPU 資源一式（PbmpmGpu）、ピース操作（PieceControl）、消去判定（LineClear）、入力（InputCapture）…と分かれ、main.cpp は約 400 行の「フレームの呼び順」だけが残る組み立て役です。実はこの形は後付けで、5,200 行の単一ファイルから挙動を 1 ビットも変えずに分割しました（方法は次節）。

苦労した点

  • DX12 のリソース状態管理 ── バッファは COMMON 生成 → 暗黙プロモーション → 提出完了でディケイ、という暗黙ルールを CPU 側で正確に追跡しないと、デバッグレイヤでコマンドリストの Close が失敗してデバイスロストする。ディスクリプタテーブルに未初期化スロットが 1 枠混ざるだけでも DXGI_ERROR_INVALID_CALL で落ちる（全スロットをダミーで先埋めして解決）
  • readback の帯域 ── 消去判定のために粒子バッファを毎フレーム CPU へ読み戻すが、全量（5.2MB）コピーするとフレーム時間が揺れて落下がかくつく。使用中の範囲だけコピーする方式に変更
  • 着地の整定 ── 「次の位置が衝突するか」だけで判定すると、小数位相次第で最大 1 セル浮く / めり込む。整数スナップ後に「めり込んでいれば押し上げ・浮いていれば引き下げ」の両方向走査で解決。ゴーストピースも整数スナップしないと毎フレームぶるぶる震える
  • 溶解相のハードドロップ ── 接地プローブが波立った水面を素通りし、プール内部に粒子を重ね打ち → 圧力爆発で「ブロック射出」になる。ピース本体の重なり判定で止める方式に変更
  • フレームペーシング ── flip モデルの Present(1) は CPU を確実にはブロックしない（実測 1600fps）。絶対時刻で 16.667ms を刻み、大幅な遅延時だけ再同期するリミッタを自作

ポイント: 決定論とリプレイを「テスト」にする

一番気に入っているのは開発フローです。乱数は固定シードの線形合同法、入力は毎フレームのスナップショットとして記録・再生できるので、同じ入力列からは bit-exact に同じゲームが再現されます。これは Debug / Release の最適化を跨いでも崩れません。

これを回帰テストに使いました。リプレイ 4 本（ライン消し / 結晶化 / 波 1 周など）の最終状態 ──「フレーム数・スコア・ピース数・粒子数」の完全一致 ── をゲートにして、5,216 行の main.cpp を 414 行まで分割する大規模リファクタを、各ステップごとにゲートを通しながら完走しています。GPU 物理を含むゲームで「挙動が 1 ビットも変わっていない」ことを機械的に証明できるのは、決定論を最初から設計に入れたからこそです。
