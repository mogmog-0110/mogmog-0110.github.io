かえるくれーぷ（Kaeru Crepe）

クレープを作りながらヒロインたちと親睦を深める 美少女ゲーム × クッキングゲーム。注文どおりにフルーツ・ソース・ホイップ・トッピングを乗せてお客さんを笑顔にする調理パートと、ヒロインとの会話を進めるノベルパートを行き来する 2 モード構成です。

Godot で書いた最初のバージョンをコミックマーケット 106 で無料配布したあと、自作の MitiruEngine へ全面移植。UI とゲーム画面をすべて HTML/CSS で組み上げ、調理の中核をプレイ可能な形まで仕上げました。

SCREENS

MitiruEngine 版の実機画面。タイトル・調理・ノベル・日締めまで、見えているもの（朝の厨房の背景、食材棚、注文ヒロインの立ち絵と吹き出し、プレート上に重ねていくクレープ、ドリンクのジューサー、結果画面の売上・好感度）はすべて HTML/CSS で描画しています。

コンセプト

傾いたクレープ屋を、ヒロインたちと一緒に立て直していくゲーム。日々の店の運営と、ヒロインとの会話やイベントを行き来する構造です。舞台は朝のダイナーです。やわらかい朝日と、磨いたクロームのカウンター。けばけばしくない、清潔で前向きなトーンを画面全体の基調にしています。

1 日のループはおおむね次のとおり。

  1. 朝のノベル（章イベントが入る日も）
  2. メインメニュー（控室の机から、ホワイトボード・ノート・PC などをパンで切り替え）
  3. クッキングシフト（リアルタイムで複数の注文をさばく）
  4. シフト終了結果（注文の達成・失敗・売上・チップ・コンボ最高記録）
  5. 夜のノベル（オプション）
  6. セーブして翌朝へ

※ 上記は目指している完成形です。現在 MitiruEngine 版では ③ クッキングシフトを中核に、① 朝のノベル・④ シフト結果（期限付きの総売上目標とヒロイン好感度）・⑥ 翌日への日次ループが骨組みまで動いており、② メインメニューと本編シナリオを順に作り込んでいる段階です。

2 つのモード

クッキングパート

マウス / タッチでクレープを作るアクション。食材棚のフルーツ・ソース・ホイップ・トッピング・アイスをプレートへドラッグして組み立てます。プレートの上ではレイヤーが重なって 1 枚のクレープに合成され、注文と一致したら包んでヒロインへ提供。余分が乗っていたり足りないと評価が下がり、待たせすぎるとお客さんは帰ってしまいます。注文ごとにヒロインが立ち絵で並んで吹き出しから注文し、待ち時間ゲージとごきげん（表情）が変化します。吹き出しにマウスを乗せると、必要な具材がアイコン＋名前のチェックリストで開きます。

クレープに加えて、まな板でフルーツを刻んでジューサーにかけたり、エスプレッソでコーヒーを淹れたりするドリンクの調理もあり、注文は「クレープ単品」「クレープ＋ジュース」など複数品に組まれます。複数の注文をリアルタイムにさばきながら、営業最終日までの総売上目標を目指す構成です。

ノベルパート + メインメニュー

シフトの合間に控室の机に戻り、ホワイトボードでストーリーを進めたり、ノートで日記を読み返したり、ラップトップで設定を開いたり、ピンボードでギャラリーを覗いたりします。視点は前・上・下・左・右の 5 方向で、それぞれに 1 つの主要オブジェクト（ホワイトボード／ノート／ラップトップ／壁の写真／キッチン入口）が割り当てられています。視線移動はカメラパン + 軽いブラーで「ぬるっと」切り替わります。

UI をすべて HTML / CSS で

本作の見どころは、ゲーム画面そのものを HTML / CSS で書いていることです。MitiruEngine は CEF（Chromium 埋め込み）を画面合成に使えるので、HUD・注文票・食材棚・プレートのレイヤー合成・評価トーストといった UI を、ふだんの Web 開発と同じ HTML / CSS で組めます。

状態は C++ 側（ゲームロジック）が一手に持ち、エンジンが宣言的バインダ（data-m-* 属性）経由で DOM に流し込む設計です。たとえば注文の必要食材は data-m-show でチップの表示を切り替え、プレート上のクレープは data-m-class で食材レイヤーの重なりを切り替えます。ゲーム固有の手書き JavaScript はドラッグの配線 1 箇所だけ。合否判定や売上計算といったロジックは JS に一切持たせず、C++ に集約しています。

HTML → C++ はドラッグの着地やボタン操作が「シグナル」として届き、C++ → HTML は状態の push のみ。境界を薄く保つことで、見た目（CSS）とルール（C++）が混ざらないようにしています。

Godot から MitiruEngine への移行

最初は Godot で書き始めました。マルチプラットフォーム書き出しや商用ライセンスの軽さ、GDScript の書き味の良さなど、十分な利点があったからです。コミックマーケット 106 で配布したのもこの Godot 版です。

そのあと、自作の MitiruEngine が ハトを育てよう（リメイク） で実際にゲームを動かせる段階に来たのを見て、本作も MitiruEngine 側に移しました。自分のエンジンで自分のゲームを完成形まで持っていく、というのがその先に取りたい姿だからです。移行にあたって、調理シーンとレシピ・食材データを現エンジンの仕様（DLL 単位のゲームコード + HTML/CSS UI + ホットリロード）へ作り直し、実機で動く形まで仕上げました。

コミックマーケット 106 で配布した Godot 版のスクリーンショット。

インフラ周り

「ゲーム本編を作るための足場」も自分で整えています。

  • デザインシステム ― DESIGN.md 1 ファイルに YAML フロントマターで配色・タイポ・スペーシング・角丸・影のトークンを宣言。朝のダイナーの配色（Butter Cream / Morning Yolk / Booth Red / Mint Shake …）はこのトークンから引いています。
  • レシピ・食材データ ― レシピは「必要食材のビットマスク + 価格 + 難易度 + 注文ヒロイン」のテーブルで定義。食材は 1 種 = 1 bit で、プレートの状態も注文も同じビットマスクで表現するので、合否判定がそのまま集合演算になります。
  • 決定論とリプレイ ― ゲーム状態を flat な POD（ポインタや可変長を持たないデータ）にまとめてあるので、セーブ・巻き戻し・自動リプレイがそのまま乗ります。
  • アセットマニフェスト ― キーと URL を分離してあるので、差し替えはコード変更なしで効きます。

完成までの歩み

コミケ 106 で Godot 版を配布したあと、コア体験を MitiruEngine 上で作り直し、調理シーンを実機で遊べる形まで仕上げました。下記が現時点で動いている要素です。

  • コミケ 106 で Godot 版の体験版を配布
  • MitiruEngine 版のゲームコード（DLL 単位、ホットリロード対応）
  • クッキングシーン（HTML/CSS UI、ドラッグ&ドロップ、レシピ判定、注文待ち、売上・チップ・コンボ）
  • 焼き工程・まな板でのフルーツカット・トッピング合成・包んで提供
  • ドリンクのステーション（ジューサー / エスプレッソ）と、クレープ＋ドリンクの複数品注文
  • 注文ヒロイン（マリア / ライカ / サチ / エリザベス）の立ち絵・吹き出し・待ち時間ゲージ・表情変化
  • 注文メニューのホバーで具材アイコン＋名前のチェックリスト表示
  • プレート上のクレープのレイヤー合成（食材を乗せると見た目が変わる）
  • 期限付きの総売上目標（達成 / 未達の判定）と、提供で上がるヒロイン好感度
  • ノベルパートの骨組み（タイトル → 朝のノベル → 調理 → 結果 のループ）
  • ステーション強化のアップグレード機構（焼き場・まな板・ジューサー等のレベル）
  • 朝のダイナーをテーマにしたデザインシステム

完成版は学園祭での展示を予定しており、シナリオ本文と最終アートを順に流し込んでボリュームを足していく段階です。差し替えやすい構造（マニフェスト分離・データ駆動）を先に作ってあるので、コンテンツは出来たそばから載せられます。
